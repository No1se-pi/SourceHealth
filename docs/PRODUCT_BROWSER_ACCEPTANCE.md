# SourceHealth — Отчёт о приёмке продуктового интерфейса (Browser Acceptance)

## 1. Обзор продуктовизации и редизайна в стиле SourceCraft

В рамках этапа продуктивизации интерфейс **SourceHealth** был полностью переработан в нативную визуальную систему инструментов разработчика **SourceCraft** (информационная плотность, нейтральные поверхности, тонкие границы 1px, чистая типографика, акцентный фирменный цвет `#f93333`).

### Ключевые архитектурные и визуальные улучшения:
1. **Полноценная поддержка двух тем (Light & Dark):**
   - **Light Theme:** нейтральные поверхности (`#f6f8fa`, `#ffffff`, `#f1f4f8`), контрастный текст `#1f2328`, мягкие разделители `#d0d7de`.
   - **Dark Theme:** глубокие графитовые поверхности (`#090d16`, `#111622`, `#171e2e`), светлый текст `#f1f5f9`, границы `#28334a`.
   - **Нулевой флеш темы (Anti-FOUC):** встроенный синхронный скрипт в `<head>` `index.html` инициализирует `data-theme` до первого рендера DOM на основе сохранённого выбора в `localStorage` (`sourcehealth_theme`) либо системных настроек ОС (`prefers-color-scheme`).
   - **Переключатель тем в шапке:** интуитивная кнопка с иконками ☀ / 🌙 и доступным атрибутом `aria-label`.
2. **Интеграция фирменных ассетов SourceHealth:**
   - Канонический логотип (гексагональная эмблема SH + словоформа "SourceHealth" с акцентным красным "Health" `#f93333`):
     - `sourcehealth-logo.png` (для светлой темы)
     - `sourcehealth-logo-dark.png` (адаптированный контрастный вариант для тёмной темы)
   - Фавиконка `favicon.png` подключена в `<head>`.
   - Бейдж версии `BETA` в навигации.
3. **Безопасность и сохранение бизнес-логики:**
   - 100% сохранение существующих API-контрактов OpenAPI, моделей DTO, маршрутизации и логики скоринга.
   - Строгая изоляция токенов: **PAT SourceCraft** хранится исключительно в сессионной памяти сервера, никогда не попадает в `localStorage` или `sessionStorage`.
   - Авторизация через Яндекс ID отделена от интеграции с SourceCraft.
   - Принцип **NO_DATA ≠ 0** соблюдён во всех компонентах: отсутствие данных явно маркируется как «Нет данных» и не занижает рейтинг репозитория до нуля.

## 2. Протестированные продуктовые экраны

### 1. Лидерборд открытых проектов (`/`)
- **Поиск и импорт:** блок быстрого добавления публичного репозитория SourceCraft с валидацией URL.
- **Фильтрация и сортировка:** выбор языка программирования (TypeScript, Python, Go, Rust и др.) и критерия ранжирования (по здоровью, лайкам, дате активности).
- **Таблица проектов:** порядковый номер, ссылка на репозиторий, язык, звёзды/лайки, дата последней активности, крупный Health Score (/100 или «Нет данных»).
- **Адаптивность:** на мобильных экранах (390px) таблица трансформируется в аккуратные карточки.

### 2. Профиль репозитория (`/repositories/:id`)
- **Шапка проекта:** название `organization/repository`, ссылка `Открыть в SourceCraft ↗`, сводный Health Score и охват оценки (`ScoreCoverage`).
- **Сетка метаданных:** основная ветка, язык проекта, лайки, последняя активность.
- **Панель действий:** кнопка запуска/повтора анализа, переход к полному отчёту, скачивание отчёта в формате Markdown.
- **История анализов:** таблица предыдущих запусков с датами, бейджами статусов, скорингом и версией профиля.
- **Оценки по 6 категориям:** канонический фиксированный порядок (Документация, CI/CD, Безопасность, Активность, Issues, Состояние кода) с бейджами доступности данных (`Данные есть`, `Частично`, `Нет данных`, `Не настроено`).

### 3. Детализация анализа (`/analyses/:id`)
- **Статус выполнения:** бейдж состояния (`В очереди`, `Анализ кода`, `Завершён`) с анимацией спиннера в процессе выполнения.
- **Экспорт отчёта:** прямая кнопка `⬇ Скачать отчёт (Markdown)`.
- **Раскрываемые факты (Evidence):** аккордеоны подтверждающих фактов по каждой категории с моноширинными ссылками на коммиты, файлы и строки исходного кода.
- **Рекомендации по улучшению:** карточки с приоритизацией P1 (Высокий), P2 (Средний), P3 (Низкий), бейджами ожидаемого эффекта (`+5 Health Score`), блоками конкретных действий и доказательствами.
- **Детализация анализаторов:** подробный аудит находок анализаторов (docs_analyzer, sourcecraft_appsec, sast, git_activity и др.).

### 4. Страница интеграции SourceCraft (`/sourcecraft`)
- **Информационный блок безопасности:** разъяснение сессионного характера PAT и невозможности утечки через браузерные хранилища.
- **Подключение токена:** форма с маскированным вводом пароля (`type="password"`), плейсхолдером `sc_pat_...` и защитой от перехвата в React state.
- **Управление подключением:** индикатор активного статуса и кнопка безопасного отключения сессии.
- **Обозреватель репозиториев организации:** поле ввода slug организации, получение списка репозиториев с бейджами приватности (`Публичный` / `Закрытый`) и запуском анализа.

### 5. Подтверждение входа Яндекс ID (`/auth/callback`)
- Аккуратная центрированная карточка подтверждения статуса OAuth-сессии.
- Отображение ID авторизованного пользователя и быстрая навигация к репозиториям.

## 4. Воспроизведение процедуры приёмки

Для автоматического повторного снятия всех скриншотов подготовлен скрипт:

```powershell
# 1. Сборка фронтенда
npm run build --prefix frontend

# 2. Запуск скрипта приёмки (поднимает mock API на 8000, preview на 5173 и запускает headless браузер)
node scripts/run_browser_acceptance.mjs
```

Скрипт проверяет создание всех 13 файлов, их ненулевой размер и корректное завершение фоновых процессов.
