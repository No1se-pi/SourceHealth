# SourceHealth Catalog & Search v2

Архитектурная и продуктовая спецификация нового блока каталога, поиска, фасетной фильтрации и аналитики открытых репозиториев платформы SourceCraft.

---

## 1. Обзор и цели

Каталог SourceHealth трансформирован из базового списка с ограниченной пагинацией (`offset 0..40`) в **полноценный поисково-каталожный опыт** для десятков тысяч публичных репозиториев SourceCraft.

### Ключевые принципы:
- **Разделение понятий**:
  - `SEARCH` — быстрый поиск уже известного репозитория SourceHealth по имени, организации, slug или описанию.
  - `CATALOG` — фасетное исследование всей накопленной базы проектов (языки, темы, баллы категорий, происхождение, свежесть).
  - `IMPORT` — явное добавление отсутствующего репозитория через API SourceCraft (поиск не выполняет скрытый импорт).
- **Соблюдение неизменности scoring-контракта**:
  - `NO_DATA ≠ 0`: отсутствие данных не приравнивается к нулевому баллу.
  - Категория **Security** рассчитывается исключительно по официальному SourceCraft AppSec.
  - Локальный SAST Scanner остаётся в категории **Code Health**.
  - **Source Soul** остаётся ознакомительным превью и не подменяет официальный Health Score.
- **SourceCraft Native UI**:
  - Использование дизайн-токенов (`tokens.css`), поверхностей (`--sh-bg-base`, `--sh-bg-surface`), типографики и цветовой семантики проекта.

## 2. База данных и индексы (Миграция 0003)

Миграция Alembic: `migrations/versions/0003_catalog_search_v2.py`

### 2.1 Расширение таблицы `repositories`:
- `description` (`VARCHAR(512)`): нормализованное текстовое описание проекта (до 500 символов, управляющие символы удалены, пробелы сколлапсированы).
- `logo_url` (`VARCHAR(512)`): проверенный HTTPS-URL логотипа из доверенных доменов (`sourcecraft.dev`, `sourcecraft.tech`, `storage.yandexcloud.net`, `avatars.mds.yandex.net`).
- `origin` (`VARCHAR(32)`): происхождение проекта (`native`, `fork`, `migrated`, `unknown`).
- `project_slug` (`VARCHAR(100)`): slug родительского проекта SourceCraft при наличии.
- `topics` (`JSONB`, default `'[]'::jsonb`): массив тегов тем проекта.
- `topic_classifier_version` (`VARCHAR(32)`): версия классификатора (`catalog-topic-v1`).

### 2.2 Индексы для масштабирования:
- `ix_repository_lower_org`: `CREATE INDEX ON repositories (lower(organization_slug));`
- `ix_repository_lower_repo`: `CREATE INDEX ON repositories (lower(repository_slug));`
- `ix_repository_likes`: `CREATE INDEX ON repositories (likes DESC NULLS LAST, id);`
- `ix_repository_last_activity`: `CREATE INDEX ON repositories (last_activity_at DESC NULLS LAST, id);`
- `ix_repository_origin`: `CREATE INDEX ON repositories (origin);`
- `ix_repository_topics`: `CREATE INDEX ON repositories USING gin (topics);`

## 3. Модель поиска и ранжирования

Поиск реализован в модуле `sourcehealth/catalog/query.py`:

### 3.1 Обработка поисковых строк:
- Очистка пробелов и защита от инъекций.
- Автоматическое распознавание полных URL SourceCraft (`https://sourcecraft.dev/org/repo` → поиск по `org/repo`).
- Поиск по организации, имени репозитория, комбинированному `org/repo`, каноническому URL и описанию.

### 3.2 Ранжирование по релевантности:
При текстовом поиске по умолчанию применяется многоуровневое ранжирование:
1. Точное совпадение `organization_slug/repository_slug == q` (ранг 1).
2. Точное совпадение `repository_slug == q` (ранг 2).
3. Точное совпадение `organization_slug == q` (ранг 3).
4. Префиксное совпадение по `org/repo` (ранг 4).
5. Префиксное совпадение по `repository_slug` (ранг 5).
6. Префиксное совпадение по `organization_slug` (ранг 6).
7. Совпадение по URL (ранг 7).
8. Подстрока в slug (ранг 8).
9. Подстрока в описании (ранг 9).
10. Прочие результаты (ранг 10).
Внутри одного ранга результаты упорядочиваются по `health_score DESC NULLS LAST, id ASC`.

## 4. Фасетная фильтрация и API

Endpoint: `GET /api/v1/repositories`

### Поддерживаемые параметры фильтрации:
- `q`: поисковый запрос (строка до 256 символов).
- `language`: фильтр по языку программирования (из фасетов каталога).
- `topic`: фильтр по теме проекта (`bots`, `web`, `ml_data`, `games`, `education`, `mobile`, `devops`, `tools`, `security`, `libraries`, `other`).
- `origin`: происхождение (`native`, `fork`, `migrated`, `unknown`).
- `health_min`, `health_max`: диапазон Health (0–100).
- `health_status`:
  - `available` — только проекты с рассчитанным числовым Health.
  - `forming` — формирующийся отчёт (активный анализ или Source Soul preview).
  - `no_data` — только проекты без числового Health.
- `security_min`, `security_max`, `security_status`: фильтрация по оценке SourceCraft AppSec.
- `cicd_min`, `code_health_min`, `activity_min`, `documentation_min`, `issues_min`: пороги по отдельным категориям.
- `coverage_min`: минимальный процент номинального покрытия данных (`nominal_weight_percent`).
- `activity_days`: активность за последние 30, 90, 180 или 365 дней.
- `sort`: `health_score`, `likes`, `last_activity`, `name`, `relevance`, `security`, `cicd`, `code_health`, `coverage`.
- `order`: `desc` или `asc`.
- `offset`, `limit`: пагинация с возвратом общего количества `total`.

## 5. Статистика каталога и гистограмма

Endpoint: `GET /api/v1/catalog/stats`

Принимает ту же модель фильтров, что и поиск, позволяя интерактивно обновлять аналитику для отфильтрованного среза.

### Рассчитываемые показатели:
- `catalog_total_public`: общее число публичных репозиториев в базе.
- `matched_total`: число репозиториев, удовлетворяющих активным фильтрам.
- `analyzed_count`: число проектов с проведённым анализом.
- `health_available_count`: число проектов с рассчитанным числовым Health.
- `health_forming_count`: число проектов с формирующимся баллом.
- `health_no_data_count`: число проектов со статусом NO_DATA.
- **Медиана и квартили (Q1, Q3)**:
  - Рассчитываются методом непрерывной интерполяции (аналог `percentile_cont` в PostgreSQL).
  - **Строго исключают NO_DATA**: в выборку попадают только числовые значения Health.
- **Гистограмма распределения Health (10 колонок)**:
  - Корзины: `0-9`, `10-19`, `20-29`, `30-39`, `40-49`, `50-59`, `60-69`, `70-79`, `80-89`, `90-100`.
  - Отдельный счётчик `histogram_no_data_count` для проектов без оценки.
  - Интерактивность: клик по столбцу гистограммы применяет фильтр на соответствующий диапазон.
- **Фасеты**:
  - `languages`: распределение по языкам программирования с количеством.
  - `topics`: количество проектов по 11 темам.
  - `origins`: распределение по источникам (native/fork/migrated/unknown).
- **Кэширование**: результаты кэшируются в Redis по SHA-256 ключу активных фильтров на 30 секунд.

## 6. Детерминированный классификатор тем (`catalog-topic-v1`)

Реализация: `sourcehealth/catalog/topics.py`

### Характеристики:
- **11 категорий**:
  - `bots`: боты для Telegram, Discord, VK, чат-боты.
  - `web`: frontend, backend, веб-фреймворки (React, Vue, FastAPI, Django и др.).
  - `ml_data`: машинное обучение, нейросети, анализ данных, LLM, PyTorch.
  - `games`: игровые движки, Unity, Unreal, Pygame, Godot.
  - `education`: учебные материалы, курсы, лабораторные работы, домашние задания.
  - `mobile`: iOS, Android, Flutter, React Native, Swift.
  - `devops`: инфраструктура, Docker, Kubernetes, CI/CD, Helm, Terraform.
  - `tools`: CLI утилиты, генераторы, линтеры, средства автоматизации.
  - `security`: аудит, SAST, сканеры, криптография, AppSec.
  - `libraries`: SDK, библиотеки, клиентские пакеты, компоненты.
  - `other`: fallback для неклассифицированных проектов.
- **Правила работы**:
  - Источник: имя репозитория, публичное описание, slug проекта, язык (secondary hint).
  - Не использует LLM (полная воспроизводимость и нулевая стоимость исполнения).
  - Не читает приватный код и секреты.
  - Возвращает до 5 уникальных тем в алфавитном порядке.
  - В UI снабжён пояснением: *«Тема определена автоматически по публичным метаданным проекта (catalog-topic-v1)»*.

## 7. Фронтенд-компоненты и UX

- **`CatalogHero`**: сводные карточки общего объёма каталога, найденных репозиториев, медианы и центрального диапазона (Q1–Q3) с поясняющей подписью.
- **`HealthHistogram`**: визуальный столбчатый график распределения проектов по качеству с интерактивной фильтрацией по клику.
- **`CatalogSearchBar`**: поле поиска с дебаунсом (280 мс), кнопкой быстрой очистки (✕), индикацией клавиатурного сокращения `Ctrl+K`.
- **`TopicChips`**: горизонтальная полоса переключения тем с счётчиками количества проектов.
- **`ActiveFilterChips`**: бейджи активных параметров с возможностью точечного удаления и кнопкой «Сбросить все».
- **`AdvancedFiltersModal`**: модальное окно глубокой настройки параметров (AppSec Security, CI/CD, покрытие тестами, происхождение, активность).
- **`CatalogPagination`**: полноценная пагинация с кнопками перехода на первую/последнюю страницу, многоточием, прямым переходом на номер страницы и выбором размера страницы (20, 50, 100).
- **`RepositoryAvatar`**: логотип проекта с безопасным отказом и детерминированной генерацией инициалов и цвета на основе имени.
- **`CategoryMiniBars`**: компактный индикатор 6 категорий в строке таблицы с цветовой индикацией и подсказками.
- **`CompareTray`**: всплывающая нижняя панель при выборе 2–4 чекбоксов для перехода на страницу сравнения `/compare`.
- **`CommandPalette`**: глобальный быстрый поиск по `Ctrl+K` или `Cmd+K`.
- **Адаптивность**: на экранах мобильных устройств (`< 768px`) таблица трансформируется в карточный список, предотвращая горизонтальную прокрутку.

## 9. Пропущенные P2-пункты и обоснование

1. **Расширение `pg_trgm`**:
   - Не включено принудительно, чтобы не создавать неконтролируемых зависимостей от суперпользовательских прав в PostgreSQL при миграции. Поиск эффективно использует B-tree индексы по нижнему регистру (`lower(organization_slug)`, `lower(repository_slug)`) и GIN по JSONB-топикам.
2. **Подсчёт размера репозитория по блобам Git**:
   - Не добавлен, так как публичный каталог SourceCraft синхронизирует метаданные без полного клонирования исходного кода каждого проекта. Подсчёт размера без клонирования был бы недостоверным.
