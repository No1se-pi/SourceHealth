# Метрики Git-активности

Все метрики ниже рассчитывает `GitActivityAnalyzer`.

## Общие правила

- входные даты должны содержать часовой пояс;
- перед сравнением даты переводятся в UTC;
- длительности выражаются в **днях**;
- день может быть дробным: `0.5` = 12 часов;
- окна считаются относительно `now`;
- границы временных окон включаются;
- будущие коммиты не попадают в rolling-окна;
- gap-метрики требуют минимум два коммита.

## Справочник

| Поле | Тип | Значение |
|---|---|---|

| `max_commit_gap` | `float \| None` | Максимальный интервал между соседними коммитами |
| `mean_commit_gap` | `float \| None` | Среднее арифметическое интервалов |
| `median_commit_gap` | `float \| None` | Медиана интервалов |
| `commits_last_7_days` | `int` | Коммиты за последние 7 дней |
| `commits_last_30_days` | `int` | Коммиты за последние 30 дней |
| `commits_last_90_days` | `int` | Коммиты за последние 90 дней |
| `commits_last_180_days` | `int` | Коммиты за последние 180 дней |
| `commits_last_365_days` | `int` | Коммиты за последние 365 дней |
| `unique_active_days` | `int` | Все уникальные календарные дни с коммитами |
| `active_days_last_30_days` | `int` | Активные дни за последние 30 дней |
| `active_days_last_90_days` | `int` | Активные дни за последние 90 дней |

## `repository_age`

Важно: это **не возраст репозитория до сегодняшней даты**.

Формула:

```text
last_commit - first_commit
```

Если в репозитории один коммит:

```text
repository_age = 0.0
```

## `days_since_last_commit`

Формула:

```text
now - last_commit
```

Обычно значение положительное.

Если во входных данных есть коммит с датой из будущего относительно `now`, значение может стать отрицательным. Анализатор намеренно не переписывает исходную историю.

## Gap-метрики

Сначала коммиты сортируются:

```text
t1 <= t2 <= t3 <= ... <= tn
```

Затем:

```text
gap1 = t2 - t1
gap2 = t3 - t2
...
```

Из них считаются:

- минимум;
- максимум;
- среднее;
- медиана;
- самый длинный период неактивности.

При одном коммите gap не существует, поэтому соответствующие поля равны `None`.

## Rolling-окна

Для окна `N` используется закрытый интервал:

```text
[now - N days, now]
```

То есть коммит ровно на левой или правой границе учитывается.

Поддерживаемые окна:

```text
7
30
90
180
365
```

## Активные дни

Активный день — календарная дата, в которую был хотя бы один коммит.

Например:

```text
08:00 commit
12:00 commit
20:00 commit
```

в один календарный день дают:

```text
unique_active_days += 1
```

а не `3`.

## Активные месяцы за 12 месяцев

Берётся:

- текущий календарный месяц;
- 11 предыдущих календарных месяцев.

Месяц считается активным, если в нём есть хотя бы один коммит, не находящийся в будущем относительно `now`.

## `average_commits_per_active_day`

Формула:

```text
total_commits / unique_active_days
```

Пример:

```text
9 коммитов / 3 активных дня = 3.0
```

## `average_commits_per_month`

Число месяцев считается **включительно**.

Например:

```text
первый коммит: январь
последний коммит: март
```

История охватывает:

```text
январь + февраль + март = 3 месяца
```

После этого:

```text
total_commits / 3
```

Для одного коммита знаменатель равен одному месяцу.

## Пустая история

Для пустого списка коммитов:

- счётчики равны `0`;
- средние интенсивности равны `0.0`;
- даты равны `None`;
- длительности, для которых нет данных, равны `None`.

Такой результат можно безопасно сериализовать в JSON.
